# Source-built quiet host v3 candidate

`Prometheus-QuietHost-v3.cs` is a new identity derived from the reviewed historical quiet-host behavior. It does not claim to reproduce the existing v2 executable. It keeps the seven fixed modes, exact pause markers, reconnect/recorder exceptions, hidden Windows PowerShell child, redirected streams and child exit codes. The production CLI accepts one fixed mode or `--probe`; there are no script/root overrides. Internal methods enable isolated tests without invoking installed scripts.

Build using `build-quiet-host.py` with explicit `--dotnet`, `--compiler` (Roslyn csc.dll), `--framework` (.NET Framework reference directory) and a new `--output` directory. It produces a deterministic GUI-subsystem .NET Framework executable and a receipt binding source, builder, compiler dependencies, framework references, command and executable hashes. The SDK is a build dependency; the candidate uses the existing Windows .NET Framework runtime. A second build to a distinct directory must match the executable hash. Existing output artifacts are never overwritten by the builder.

Qualification: `pytest tests/test_quiet_host_v3.py tests/test_host_agent.py`. Tests use temporary roots and generated scripts, verify GUI subsystem, fixed modes, invalid arguments, missing scripts, both pause markers, exact exceptions, actual no-console child processes, both output streams and exit propagation. They do not install tasks or invoke live background jobs.

## Consumer migration is not applied

The proposed installed path is `%LOCALAPPDATA%/Prometheus/Prometheus-QuietHost-v3.exe`. Existing consumers still reference v2; building v3 alone does not activate it. Preserve both current v2 locations and their hashes for rollback. The two existing consumer paths (task root and Lifecycle's QuietBackground subdirectory) need an explicit ownership-aware migration. Do not run the current name-only task rewriting script as that migration.

Before any consumer change, qualify the complete signed package and verify every selected task's exact single action, executable path, mode and task path. Foreign or unknown tasks must remain untouched; failure to establish ownership must prevent any mutation. Save original task definitions and existing files, preserve running Desktop Commander and backup work, and retain eject mutex/marker behavior. A separately reviewed migration must update both task and Lifecycle consumers to the same candidate root and preserve existing runner fallback. Installer ownership checks must recognize only exact intended v2/v3 actions; do not broaden matching to filenames alone.

No v3 install/repair/signature/readiness claims follow from the source build or isolated tests. Physical eject/reconnect, task migration, rollback and live desktop behavior remain separate integration acceptance.

Revision 2 safety gates: unreadable pause markers (I/O, access denial or security error) suppress work modes; reconnect and recorder retain their explicit exception so recovery/evidence collection can continue. The builder snapshots source, itself, selected compiler/launcher/reference inputs and the compiler's .dll/.json dependency membership before compilation, compares all hashes afterward, and rejects changed inputs without creating a success receipt. Any failed build artifact remains available for diagnosis and cannot be overwritten by rerunning into that directory. This is a stable pre/post check, not filesystem locking or protection against a malicious transient change that is reverted between snapshots.
