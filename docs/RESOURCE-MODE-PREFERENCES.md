# Owner project scheduling preference

Automatic (null) or one of Idle, Balanced, Performance, Battery Saver and Critical Recovery is persisted atomically in Maintenance/ResourceHistory/mode-preference.json. This backup-covered file is bounded, strictly versioned and loaded when the service starts. Invalid saved data selects Automatic with a visible diagnostic. Invalid owner input never writes. A failed atomic replacement retains the prior preference. If readings fail after a successful save, the response explicitly reports the saved preference and conservatively enters Critical Recovery.

Status and project review show requested/effective mode, reason, protective override and pending dwell. All project scheduling seams use the saved request, including refreshed approval reservation. Real critical conditions retain precedence; the stronger voluntary Critical Recovery pause also dominates low-battery mode and enters immediately. Battery protection overrides other owner preferences. Leaving recovery retains minimum dwell. Existing RAM, disk, CPU and battery admission guards cannot be relaxed by Performance.

This is a project scheduling preference, not an operating-system power plan. For project-check admission, Idle, Balanced and Performance primarily select/display mode; they do not implement model unloading, increased concurrency, EcoQoS or new background polling behavior. Critical Recovery defers project admission. Battery Saver retains existing battery-budget protections. The wider five-mode lifecycle in the SSD plan remains unfinished.

## Optional specialist stages

New specialist admission receipts are version 2 and include requested/effective mode plus dwell evidence. Idle, Battery Saver and Critical Recovery defer new optional specialist inference; stricter owner intent takes effect even while the displayed mode is dwelling. Automatic foreground work is not blocked by a prior automatic Idle display during dwell. Existing hardware, power, model and context guards remain mandatory in Balanced and Performance. Each role refreshes its sample, and a mode change between roles prevents the next invocation. Deferred stages remain incomplete, never passed. Historical version 1 receipts remain validated under their original observation-only contract and are not evidence that mode admission ran. Running inference is not cancelled by this slice; other model paths, OS tuning and general model lifecycle remain outside scope.
