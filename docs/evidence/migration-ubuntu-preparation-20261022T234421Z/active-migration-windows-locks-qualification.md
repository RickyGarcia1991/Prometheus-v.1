# Generated Windows migration mutex qualification

49 tests passed on Windows, including native child-process contention for all 27 outer and three runtime mutex roles; partial-acquisition reverse cleanup; native abandoned outer/runtime mutex acquisition with explicit successful or refused revalidation; same-thread ownership/order; runtime release before restart; six unsupported session contexts; changed session observations; injected open/wait/release/close failures; and production-name refusal.

All names are generated Local\PrometheusMigrationFixture-<random-token>-<role>. No production mutex, task, application process, host file or drive pointer was used. There is no production activation adapter. Native child processes use the actual base Python executable (not a venv shim), bounded 20-second self-release and direct subprocess cleanup. Abandonment is generated by exit of only that owned child while a parent observation handle keeps the mutex object alive.

The owner retains native handles on one thread. Acquisition is nonblocking and ordered: ReconnectEnrollment, Eject A through Z; then UsbLifecycle, Arrival, HostAgent only under the outer group. Partial acquisition releases in reverse. Abandoned ownership does not yield usable scope until a caller-provided protected-state revalidator returns literal True. Cleanup attempts release and close independently for every acquired handle. Any native cleanup uncertainty poisons the owner, records unresolved handle/ownership state, and refuses reuse/restart. Tests injecting failure-return codes first perform their native cleanup to avoid leaking test resources; this proves fail-closed bookkeeping and independent attempts, not that a genuinely denied native cleanup can always be repaired.

Session checks require current caller/task/observed-worker session equality, reject session zero, changed observations and nonfixture mode. These checks do not exclude a competing logon session that appears after observation. Supported scope is isolated cooperative same-session fixture testing; production cross-session exclusion remains an unresolved adapter gate.

Initial 44-test native pass is retained separately. Review found cleanup handle-accounting gaps and the venv launcher ambiguity; the final 49-test suite includes their corrections. The initial system-Python invocation lacked pytest and was not a product failure. The core migration state machine was not changed. Independent reviewer validation is separate from this implementer report.
