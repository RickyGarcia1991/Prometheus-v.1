# Generated Windows migration filesystem store qualification

This component implements only generated-root filesystem callbacks for the existing migration core: authenticated phase journal, create-only old HostAgent backup, and staged replacement/readback. It does not provide task disable/stop/restore/start, production authorization, a live provider, or an activation entry. `production_activation_available` remains false. Core source is unchanged.

The fixture verifies the actual pinned signed R5/R7 closure using the existing native-chain PowerShell verifier and authenticates the original synthetic R5 enrollment receipt with Windows DPAPI. The verifier requires an R7 completion view, so a separate preserved view contains exact original authority/receipt/task/plan plus signed R7 files. That view is explicitly only a trust-verification view. Actual target hashes are independently checked: four unchanged runtime files, plus the allowed old/new HostAgent for the authenticated phase. Original receipt, authorization, task configuration, canonical plan and generated-root marker are rechecked before mutating callbacks.

The store key uses actual Windows current-user DPAPI with a distinct migration-store domain and root/transaction binding. It does not reuse pointer-provider entropy. Missing/corrupt keys on resume refuse, including an empty existing transaction directory. Initial key creation requires exact old target bytes. Journals use the existing core HMAC seal and exact canonical schema; empty, malformed, foreign and skipped-phase records refuse. Journal pending files are create-only, flushed and read back before atomic replacement and a further authenticated readback.

Backup and replacement ownership is established by authenticated transaction-bound nonce intents before file creation. Matching bytes alone do not establish ownership. Backup receipts bind the exact old bytes and nonce; replacement receipts bind exact new bytes and nonce, and post-replacement acceptance also checks the old backup and refuses leftover staging. Unknown, partial, conflicting or foreign evidence is preserved on refusal. The generated mutex primitive serializes cooperative same-session operations on one thread. Fixed operation paths and their ancestors reject reparses before access.

Qualification uses fresh direct Python processes and `os._exit` interruptions before/after journal publication, backup creation, replacement and readback. Separate mid-write process exits leave partial files that fresh processes refuse without modifying evidence. These results concern process interruption and the observed Windows filesystem API behavior. Flush/fsync and replace do not prove power-loss durability. Cooperative checks do not claim protection against arbitrary concurrent same-user malicious filesystem mutation, root copying or restoration of a complete earlier valid state.

The caller/core owns task lifecycle sequencing. A valid filesystem journal phase alone does not assert that real task operations occurred, and this component cannot serve as a completed production migration verifier. The tests may write later phase records solely to verify filesystem acceptance/refusal rules; they do not run task lifecycle operations. Full provider composition and activation remain unavailable.

Test counts, exact source/test/evidence hashes and independent review are recorded in the accompanying receipt after the final frozen run. Generated roots and verification views are preserved locally for evidence; no installed path, production process/task, drive pointer or removable-drive file is mutated.

Final frozen qualification: 47 tests passed in 199.06 seconds, with no failures or skips. Independent review additionally passed eight separate regression cases in 30.88 seconds and reran six selected native interruption cases in 37.93 seconds, with no remaining actionable findings. The latter six overlap the main suite; they are independent reruns, not six additional unique cases.

Preliminary history: 36 tests passed in 122.63 seconds on an earlier draft; that console result remains in conversation, but its XML was overwritten and is not claimed as a preserved artifact. The expanded 45-case run passed in 191.29 seconds while final review edits were being made; its XML is preserved separately as active-migration-windows-store-preliminary45-tests.xml. Neither preliminary run is the final frozen qualification. The final 47-case XML is active-migration-windows-store-frozen-tests.xml, and exact source/test hashes are in the receipt.
