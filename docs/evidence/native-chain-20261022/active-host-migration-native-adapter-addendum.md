## Concrete files and provider mapping

Implement `active_host_migration_windows.py` as the provider owner, with a fixed-function `ActiveHostMigration.Native.psm1` for Task Scheduler/package/profile observations and constrained task enable/disable/start operations. The Python owner retains native process/file handles and mutexes on one thread across callbacks. A new PowerShell subprocess per callback must never own the mutex lifetime: Windows mutex release is thread-affine. There is no generic command, task name, PID, or arbitrary target-path interface.

## Immutable receipt and read-only preflight

Add `inspect-active-host-migration.py` with explicit inspect-only behavior and a stdout report. It derives the real context using the current Windows profile API and unique matching `Win32_UserProfile`, checks ancestors/final path resolution, current SID/session, and machine fingerprint. It reads actual authorization without minting or repairing it. Resolve the unique existing task and matching original authenticated receipt; report ambiguity rather than selecting the latest folder.

The original R5 receipt contains package/id/file history and historical disabled state; it has no host/auth/task-XML hashes. Capture those current observations separately into the migration plan and bind the exact historical receipt digest. Never represent its historical `task_enabled=false` as proof the current task is disabled. The independent activation history and current scheduler observation establish the current state.

Preflight validates signed closure, original receipt, all five old runtime files, current task XML/identity/flags, exact pair and independent application/controller/Commander observations, pause/eject indicators, profile/session eligibility and existing migration evidence. It writes neither live state nor a completion receipt; a caller may save its report in the workspace. It cannot promise later mutability safety: execution repeats verification under locks. Distinguish refusal, observation incompleteness, pending owned recovery, completed migration, and eligible-but-not-executed.

For migration-aware post-completion consumers, retain the full chain: original R5 receipt → authenticated plan/completed migration → verified signed R7 closure/current runtime. Existing R5 activation/recovery consumers remain unchanged and continue rejecting R7. Native fixture `active-migration-native-chain.ps1` is the integration starting point, not a ready production consumer: replace synthetic observations with real reads and extend lock coverage across native verification and HMAC acceptance. Do not ship its `CreateReceipt` fixture mode into production.

## Blocking concurrency and recovery decisions

All existing lifecycle mutexes are session-local. Observing no other-session worker once cannot prevent one starting later. A production adapter must prove the supported same-session deployment contract and exclude competing sessions for the entire mutation interval; if that cannot be established with current R5, refuse live migration. A cooperative global/session coordination change would require a separately reviewed signed release/operating procedure. Do not promote the existing fixture snapshot into a cross-session guarantee.

Task Scheduler has no general compare-and-swap update based on exported XML. Revalidation narrows a race but does not make arbitrary concurrent task re-registration safe. State the supported exclusive administrative-operation contract and refuse mismatched observations; a stricter guarantee needs separately implemented exclusion. Stop only the retained original process handles even if the task is replaced during a race.

Recovery preserves ambiguous file/task/receipt state and reports the last authenticated intent, verified backup, current identities, and bounded recommended next action. Do not auto-enable a changed task, remove a foreign file, infer ownership from matching bytes, or roll back merely because the operation timed out. A lost Start completion requires proof of the existing current pair; original historical PID strings are not its identity.

Native filesystem/DPAPI/journal interruption matrix: before/after flush, replacement, readback, backup creation, enabled-state restoration, Start and complete publication; independent process kill/recovery; foreign/ambiguous backup or target; denied permissions; changed key/receipt; prove no evidence deletion.

Assert exact original task restoration, zero starts for stopped baselines, one owned pair after lost completion, five R7 runtime hashes, unchanged original receipt/auth and surviving independent workers.
