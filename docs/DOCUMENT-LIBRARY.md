# Personal document library

Prometheus can import UTF-8 text, Markdown and CSV files, DOCX documents, and PDFs with selectable text. It retains the original file and indexes text locally. Imported text is evidence to quote and inspect; importing a document never executes its code, macros, links or embedded objects.

The current import limits are 8 MiB per file, 400,000 extracted characters, 384 passages, and 100 PDF pages. Scanned PDFs need OCR before import. Complex page layouts and tables can lose reading order during text extraction; check the original before acting on an important passage.

## Versions and dates

Importing the same filename updates that document while retaining its earlier versions. Importing identical content and identical source metadata twice does not create another version. A supplied document ID can explicitly associate a differently named file with an existing document.

Each version records the SHA-256 hash, original filename, import timestamp, source URL and source publication date, when supplied. An import timestamp does not prove a source is current. Unknown source dates remain unknown. By default, search returns only the latest imported version of each document; `include_history=True` also searches earlier versions and labels whether each result is the latest.

Originals are content-addressed under `originals/`; metadata, passages and the FTS index are in `documents.sqlite3`. Keep both in backups. Nothing is uploaded by the library.

## Keyword and meaning-based search

Keyword search is always available and uses a SQLite FTS index with literal search terms. It ranks matches and returns bounded passages with locations and source metadata.

Meaning-based search is optional and uses real vectors generated by an installed local Ollama embedding model. The application supplies a memory gate and runs indexing on its one-job worker so embedding inference does not compete with chat inference. Insufficient memory, unavailable Ollama, missing model digests, invalid vectors or model errors preserve keyword search and return an explicit status.

Indexing processes two passages per model call and at most 32 passages on import. `index_missing_embeddings()` can finish deferred work later. Semantic search examines up to 5,000 indexed passages, preferring newer passages when the library exceeds that bound, and combines ranked semantic matches with ranked keyword matches. The result names the actual retrieval method and the model identity. This bound is visible as `semantic_scan_limit`; it is not a claim that all older passages received semantic comparison. Keyword search still covers the whole library.

Vectors are kept separate by installed model digest and embedding configuration. A model identity change requires new vectors. If dimensions change under the same identity, search invalidates those vectors, reports that reindexing is required and continues with keyword results. No synthetic vectors are used in production.

The search ranking tests use deterministic vectors to validate storage, fusion and fallback; they do not establish the quality of the installed model. Live model quality and latency must be measured separately on hardware with sufficient free memory.

## Python integration

```python
from prometheus_assistant.document_library import DocumentLibrary, OllamaEmbeddingClient

library = DocumentLibrary(
    data_dir,
    embedding_client=OllamaEmbeddingClient(),
    embedding_allowed=has_memory_headroom,
)
record = library.import_file("notes.pdf", source_date="2026-01-02")
record = library.import_bytes("notes.md", b"Local project notes")
current_versions = library.list_documents()
all_versions = library.list_documents(include_history=True)
result = library.search("renewal requirements", limit=5)
progress = library.index_missing_embeddings(limit=32)
```

`list_documents()` returns a list of metadata objects. Import returns one metadata object plus `duplicate`, `embedding_status` and indexing progress. Search returns `retrieval`, `semantic_status`, `model_identity`, `results` and evidence flags. Each result includes `document_id`, `version_id`, `title`, `source_url`, `source_date`, `imported_at`, `sha256`, `original_path`, `original_filename`, `is_latest`, `location`, `excerpt`, retrieval method and ranking signals. Scores are retrieval rankings, not factual confidence.

Use a separate library directory, such as `Prometheus-Data/Documents`, within the existing portable data directory. Calls open and close their SQLite connections. The UI must serialize mutating/indexing work through its worker and must not expose unrestricted server-side filesystem paths for import; user-selected browser upload bytes are the preferred UI boundary.

## Parser and archive limits

DOCX files are read as bounded ZIP/XML data without extracting files. Path traversal, links, encrypted entries, duplicate names, high compression ratios, oversized archives and XML entity declarations are rejected. Only the main document text is indexed; images, macros and relationships are not followed.

PDF parsing runs in a child process with a 20-second deadline, a 192 MiB process memory budget and 4 MiB per decoded stream limit. Unsupported host memory controls cause a clear import error. The parser never opens a PDF viewer or runs embedded PDF actions. Temporary PDF copies live inside the library directory and are removed when parsing completes.

The release includes **pypdf 6.10.0**, copied from the existing Codex Python runtime, with its BSD-3-Clause license and distribution metadata. No new download was performed. File hashes and provenance are in `pypdf-provenance.json`; the bundled license is at `src/pypdf-6.10.0.dist-info/licenses/LICENSE`. The signed release manifest also covers the bundled parser. These caps reduce resource risks; they do not replace operating-system security updates or a tested backup.
