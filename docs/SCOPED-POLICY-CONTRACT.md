# Completion contract — dev6 scoped application policy

Base: 46c98578d6b2f24f1e5ed1aa4ca169f0b877876f. This isolated candidate is the sole new implementation. Existing working copies and prior evidence remain preserved. Publishing, signing and activation require the coordinator's independent approval of REVIEW-READY.json.

## Acceptance criteria and binding decisions

1. Shared decisions run at registered Core execution, HTTP submission and queued execution, direct workspace dispatch, both CLIs, provider adapters and selected background targets. Unknown dispatches and caller-supplied risk/principal/approval fields fail closed. Refusal regressions must prove no executor/provider effect. The inventory names enforcement sites but is not itself enforcement.
2. Existing defaults and exact-plan approvals stay compatible. The new host override is deny-only. Grants supplement application authorization and never replace owner authentication, origin/token/CSRF, signatures, path/no-link/DNS checks, provider credentials/reviews, capture restrictions or OS authority. Plain unregistered Core executor dictionaries are rejected; trusted extensions must construct a ToolRegistry with explicit ToolSpecs.
3. Grant support is deliberately exact and limited to research/public and project/tests. An enrolled, currently authenticated owner must separately review and issue each grant. Arguments are normalized and hashed, provider is an existing named provider, and tests bind the canonical project path. No wildcards, prefixes, caller-selected principal or implicit live grants. A grant lasts 1–900 seconds and permits 1–5 attempts; a review lasts 120 seconds and can be issued once.
4. The host derives MachineGuid/machine-id binding and owner public-credential identity. Source and effective normalized host-policy revision invalidate stale grants. The host-local ledger, continuity witness and process lock persist grants, expiry, revocations, spent attempts and invocation IDs across ordinary application restarts. Portable data backup/restore does not include this authority. Budget reservations commit before effects, errors spend attempts, and revocation serializes with execution; revocation cannot undo an already dispatched effect. Test threads, second-store interleavings and spawned processes.
5. Missing/mismatched/corrupt ledger continuity fails closed. A partial or older DB/witness replacement is detected; running-process high-water state detects restoring both files. Wall or monotonic rollback retires old grants while allowing a new explicit review in the new clock epoch. A reboot cannot extend the original wall deadline; a lower monotonic value retires old grants. Malicious same-OS-account or administrator restoration of ALL host authority before process start is outside this boundary: no hardware/external monotonic service is available. Do not claim resistance to that actor or manually clear invalid authority to revive grants.
6. Review displays exact capability, user-entered arguments, canonical safe target, lifetime, attempt count and policy revision. Persistent records store scope digests and minimal target identifiers, not raw query/argument content. Inspection/revocation are owner scoped. Lock/authentication loss clears UI observations; queued Core work revalidates owner authority immediately before execution. No general shell, remote, capture, home or secret-bearing capability receives a grant.
7. Qualification uses actual agent and CLI helper calls with synthetic disposable memory, host ground truth, sequential feasible local models and retained raw responses. Cover hardware, unavailable-device uncertainty, conversation, exact arithmetic, structured instructions, retrieval/memory and source-tool selection. Deterministic facts/fallbacks are distinguished from generated prose and planner reliability; this limited sample does not promote a model.
8. Audio and portability results distinguish source/unit, software/installed and physical evidence. Verify synthesis/format/actual transcription, supported cooperative drain and isolated handle release; prepare host-local diagnostics. Human acoustic acceptance, cable removal/reinsertion and second-host operation remain physical work unless independently observed.

## Compatibility and external authority

The public source coverage map in docs/PERMISSIONS-BOUNDARIES.md enumerates the implemented commands, routes, providers and background seams. This is an application dispatch policy, not an OS sandbox for arbitrary Python callers. Internal data transformation helpers retain their caller contracts. Signed bootstrap/verifier/repair/signing, Drive Controller/Host Agent, launcher session locks, recovery tools and OS safe removal keep independent authority and are not represented as migrated.

No private conversations, credentials, keys, weights, host environments or machine logs enter public Git. Resolve volume labels uniquely. Preserve signed rollback releases and memory/owner data. No forced stop, dismount, media format, Ubuntu activity, cloud inference or model download. New ambient recording requires an announced bounded test. Release evidence separately binds source commit, built payload, installed release and physical acceptance. Do not call the entire project complete while physical acceptance remains open.
