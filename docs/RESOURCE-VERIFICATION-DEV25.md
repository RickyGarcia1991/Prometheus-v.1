# Resource verification and recovery — 0.8.0.dev25 candidate

Project editing can select related existing files automatically and present their
combined changes for owner review. Interrupted work exposes recovery choices.
The exact approval includes available RAM, disk, CPU and battery observations,
resource-admission reasons and verification evidence tied to the candidate.
Application rechecks admission before writing and releases its lease on failure.

Completed project checks report native Windows direct-process peak working set,
CPU time and OS transfer counters. Successful complete workloads train bounded
history separated by computer and check family. Cancelled, timed-out, failed,
missing or partial runs do not improve forecast confidence. A later proposal
uses retained observations with a conservative margin and baseline RAM floor.
History/reporting failures preserve the actual result and undo receipt.

Verification compares the exact file snapshots and real check results. It
distinguishes pending checks, failed checks, unavailable coverage and verified
results. Evidence does not replace the owner decision. Denial makes no proposed
project change; successful undo restores the original bytes.

Portable runtime startup now derives executable and model paths from the chosen
resource root. GPU discovery reliability remains a separate follow-up; live
acceptance used a temporary CPU-only session. Descendant resource accounting,
physical disk pressure, measured battery drain, automatic remote job dispatch
and independent multi-model review remain on the expansion roadmap.

Development evidence before packaging: 2,371 regression tests passed with four
documented skips; final calibration fixes passed 65 affected tests; 82 UI tests
passed, then both affected UI suites passed after the final status correction.
Live owner-authenticated browser acceptance exercised a real model proposal,
approval, actual checks, saved history, a forecast on the next proposal, denial
and exact-byte undo. Counts overlap; they are not additive unique totals.
Fresh package results belong in the external release receipt.

The signed package excludes private memory and host signing material. Preparing
it does not install it; the installed dev24 release remains the active baseline.
